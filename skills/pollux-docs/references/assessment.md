# Assessment Report — structure and rules

Output: **PDF, Paper mode, 2–4 pages**. Technical audit deliverable after a cloud assessment.

Ref format: `AS-YYYY-NNN`.

## Required inputs

- Findings: area, summary, severity (alta/media/baja), risk
- Current state narrative (1–2 paragraphs)
- Recommendations (numbered, 4–6)
- Proposed roadmap (phase / action / priority)
- Next steps + sender

## Structure

```
[BAND 64mm] title + client
[01 — RESUMEN DE HALLAZGOS]   table (área / hallazgo / severidad) + count line
[02 — ESTADO ACTUAL]          narrative
[03 — HALLAZGOS DETALLADOS]   block per finding: area · severity · summary · risk
[04 — RECOMENDACIONES]        numbered
[05 — ROADMAP PROPUESTO]      table (fase / acción / prioridad)
[06 — SIGUIENTES PASOS]       meeting CTA + contact
```

## Rules

- Severity "ALTA" in orange bold; media/baja in navy — red is forbidden
- No prices in an assessment (pricing goes in the follow-up offer)
- Findings blocks use KeepTogether (never split)
- Facts only: no marketing language inside findings

## Verification

- [ ] Severity count in summary matches detailed findings
- [ ] Each finding has explicit risk
- [ ] Roadmap priorities coherent with severities
